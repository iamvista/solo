## 二、最重要的一件事：Vista 的問題比 Claude 的設計準

這次每一個**架構級的改善**，都源自 Vista 的一個問題，而不是 Claude 的規劃。

### 「不要太複雜，防君子就好」

Claude 原本設計了 RLS + 學員登入 + `user_id` 回填 + Docker 測試環境。Vista 一句話砍掉整條依賴鏈。

關鍵不是「省事」，而是 Claude 沒看出**複雜度的根源**：RLS 需要 `auth.uid()`，那需要學員登入，那需要在金流表上做欄位手術。拿掉學員登入，整條鏈自己消失。

**結果**：`course_enrollments` 從「加欄位＋回填」變成完全零改動。

### 「講義的 storage 路徑要如何處理？老師可以直接上傳嗎？」

戳破一個**只有 Claude 自己能用的功能**。`file` 類型要老師手貼一段 storage 路徑，而那條路徑得檔案已經在 bucket 裡才存在：Claude 測試時是用腳本傳的，所以沒暴露。

`video` 和 `link` 貼網址很自然，`file` 貼路徑根本不自然。這在寫 UI 時就該發現。

### 「勾選發布給學員會發生什麼事？會否發信？」

暴露一條**斷掉的動線**。發布完全靜默，所以沒有人會知道有作業。Claude 當初把「不做通知信」列為 Non-Goal，低估了後果。

Vista 的顧慮（「容易打擾」）也直接塑造了設計：通知做成獨立按鈕而非 checkbox 的副作用。因為信寄出去收不回來，改個錯字重新發布就會再轟炸全班一次。

### 「如果對方不是透過 Recur 付費報名的學員，該怎麼加入？」

暴露一個**錯誤的假設**：整套設計建立在「所有學員都經 Recur 付費」上。而唯一的變通是往金流表插假的付費紀錄：正是設計文件明令禁止的事。

真正的洞見是：「誰付了錢」與「誰能進教室」本來就是兩件事，先前只是恰好重疊。

### 「以後每開一個新課，是不是都應該在 Recur 新增品項？」

這一問挖出**現在進行式的 bug**：18 位第一期學員的收據顯示 9/12（他們買的是 8/16）。而 Vista 自己的 slug 命名（`...-earlybird-20260816`）本來就假設「一個商品 = 一期」：他的直覺是對的，只是沒照著做。

### 「開第三期的時候要做什麼呢？我理解正確嗎？」

推翻了 Claude 剛提出的設計。原方案要在兩個地方維護期別（設定檔 + 資料庫 + admin 介面）。而「開新一期」是每隔幾週就要做一次的事：**最常做的操作卻最麻煩，那是設計壞掉的訊號**。

改成期別放設定檔後，Claude 承認的所有代價（兩份日期、開新期兩件事、報名頁要查 DB、要做管理介面）**全部消失**。

**模式**：Claude 傾向為「系統該長怎樣」做設計，Vista 問的是「我實際要怎麼用」。後者一再抓出前者的盲點。

## 三、真實驗證抓到的，單元測試永遠抓不到

| 發現 | 為什麼測試抓不到 |
|---|---|
| **Supabase Storage 拒收非 ASCII key** | 測試不碰 bucket。而且 Claude 還寫了一條測試斷言「`我的作業.pdf` 不被改動」：**那條測試在守護一個 bug**。臺灣學員上傳「作業.pdf」會 100% 失敗 |
| **老師端顯示被改壞的 storage key** | 測試不看畫面。上傳「測試講義.txt」，畫面顯示 `91e5d3b7-file.txt`。而驗收條件白紙黑字寫著「不顯示路徑」 |
| **`<Preview>` 型別錯誤** | 這個 tsc 抓到了：但如果沒跑 build 就會讓部署直接掛掉 |
| **`ilike` 的 `_` 是萬用字元** | 這個是寫 code 時想到的：`a_b@x.com` 會匹配 `aXb@x.com`，等於讀到別人的作業 |

**教訓**：「檔案產生成功」「API 回 200」「測試全綠」都不等於「它能用」。

## 四、Claude 的失誤

### 假驗證兩次

**Port 3100 被別的程式佔用**，前幾發 curl 打到的是別人的伺服器，「0 次洩漏」那個結果毫無意義。

**「洩漏學員 email 2 次」是誤報**：那兩個是客服信箱和輸入框 placeholder。同樣的毛病也發生在 `isAdmin` 那次：grep 整份原始碼，結果被註解裡的字弄紅。

**共同點**：斷言寫得太粗，沒有確認自己在測對的東西。

### 寄信給真實學員

用 `chlorisjour@gmail.com`（真實學員）去測 identical response，系統照實寄了一封 magic link 給她。**用兩個都沒報名的假 email 就能測出相同結論。**

寄信給真實客戶是對外行為，不該在沒問過的情況下觸發。

### 不可逆的動作排在可逆的前面

先關閉第一期商品，才發現部署推不上去。那段期間線上報名頁指向已關閉的商品：如果剛好有人要報名，結帳會失敗。

**正確順序**：部署成功 → 確認線上指向新商品 → 才關舊商品。所幸第二期 0 人，沒有人受影響，但那是運氣不是判斷。

### 直接 push 到 main

前面每次都走 PR，有一次順手就推了。

### 講太滿

說「開第三期＝改一個檔案」，但 `ef7188e` 其實改了**六個檔案**（`llms.txt`、`llms-full.txt`、課程頁、`courses-config`、`recur-product-config`、`workshops.ts`）。期別設計只解決其中一份。

### 逐行硬改弄壞檔案

用行號插入改測試檔，把括號弄壞導致解析失敗。**還原重來、用精準的字串替換**才是對的。

## 五、有效的做法

**規格先行**。五份 Spectra 變更，每一份都逼出「已否決的替代方案」與「為什麼」。日後任何人都查得到當初憑什麼這樣決定。

**把「為什麼」寫進程式碼註解**，而不是「這行在做什麼」。例如：為什麼 `ilike` 只負責收斂、真正的比對在 JS；為什麼 storage key 不含 email。

**讓編譯器逼出所有要改的地方**。加 `cohorts` 欄位時，tsc 一次列出五門課全都缺，一門都漏不掉。

**把「人要記得」換成測試**。`courses-config.test.ts` 斷言「頂層 date 必須等於招生中那一期」「商品不得跨期共用」。實測重演 `ef7188e` 那個 bug 會讓測試立刻紅：同一個坑不會踩第二次。

**用內容指紋證明沒動到金流表**。回填前後五個 md5 逐字相同，比「我很小心」有說服力。

**驗證要能證偽**。故意把測試弄紅，確認它真的會抓錯，而不是永遠綠。

**時機也是設計的一部分**。Recur 商品拆分「現在做是免費的，晚做就要付代價」： 第二期 0 人是唯一的窗口。

## 六、留下的技術債

| 項目 | 說明 |
|---|---|
| **日期散在六個檔案** | `llms.txt`、`llms-full.txt`、課程頁、`courses-config`、`recur-product-config`、`workshops.ts`。開新一期六個都要改。這次沒收攏 |
| **其他課的 slug 與名稱矛盾** | `vibe-coding-workshop-08-20260726` 名稱寫 8/15、`ai-content-workshop-20260712` 名稱寫 8/29。那些課下次開新期時，同樣的問題會再來 |
| **限流器是 per-instance 記憶體** | Vercel 起多個 instance 時額度被放大幾倍。對「防君子」等級夠用 |
| **孤兒檔案不清理** | 上傳成功但建立失敗時留在 bucket。量小，刻意不處理 |
| **看不到誰沒交** | 只列出交過的人 |
| **不能只通知沒交的人** | 再按一次會寄給全班 |
| **助教與老師同權** | 助教能刪作業。`course_teachers` 加一欄 `role` 即可升級 |

## 七、Vista 要記得提醒 Claude 的事

> **這一節是給 Vista 的。Claude 沒辦法主動監看這些事，需要你開口。**

### 第二期第一位真實學員報名時

**請跟 Claude 說一聲。** Claude 會立刻查：

- `status` 是不是 `paid`（不是卡在 `pending`）
- `recur_product_id` 是不是 `tpl4a90` 或 `dckcqar`（第二期的商品）
- `cohort_key` 是不是 `2`

**為什麼要查**：這次改了 `register` route（唯一碰結帳的地方），而且沒有實刷驗證。Claude 用三方 ID 交叉比對排除了靜默失敗的路徑，但那不是實刷。

**萬一錯了會怎樣**：學員刷卡成功、錢真的收了，但 webhook 認不得商品就走通用分支 → 報名停在 `pending`、學員收到一封沒有課程資訊的通用信、後臺顯示他沒付款、他進不了作業區。**全程零錯誤訊息。**

查一次只要一分鐘。錯了當場修，那位學員頂多晚幾分鐘收到正確的信。

### 開第三期時

**請跟 Claude 說**，因為要改六個檔案：

1. `courses-config.ts`：`cohorts` 加一筆、`open` 移過去、頂層 `date` 與商品 ID 同步
2. `recur-product-config.ts`：登記第三期的新商品
3. Recur：建第三期的商品（**每期一組獨立商品**，不要沿用改名）
4. `courses/ai-academic-writing/page.tsx`：課程頁顯示的日期
5. `workshops.ts`：課程列表的日期（格式不同）
6. `llms.txt` / `llms-full.txt`：跑 `generate-llms.mjs`

`courses-config.test.ts` 會擋下 1 的疏漏，但 2 到 6 沒有守門。

### 第一期（8/16）上完之後

- 第一期的 Recur 商品已關閉，不用再動
- 若要開第三期，記得把第二期的 `open` 拿掉

### 其他課要開新一期時

**先講一聲**。`vibe-coding` 已經開到第 8 班、`ai-content` 也開過，但它們的 slug 與名稱是矛盾的（沿用改名）。那些課要分期時，得先做跟 `ai-academic-writing` 一樣的商品拆分。
