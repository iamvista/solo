## 二、新版特色

### 1. 視覺專業度大幅提升
深藍 + 金色的配色方案取代了原本的白底 + 紅色主色，從「工具型網站」的觀感升級為「高端進修平台」。整體色彩語言一致：Hero、Featured 卡片、企業內訓區塊都使用相同的深藍底色，建立品牌視覺記憶。

### 2. AI 生成封面圖
使用 OpenRouter API（GPT-5 Image Mini）為每門課程生成獨特的抽象幾何風格封面。每張圖都以深藍金色為主調，與品牌色彩一致，並根據課程主題呈現不同的視覺意象（如 AI 指揮中心的電路板、創新工作坊的燈泡幾何圖形、資產安全的盾牌等）。

### 3. 分類篩選機制
新增客戶端即時篩選功能，使用者可透過膠囊式 Tab 按鈕快速切換「全部 / AI 應用 / 創新思維 / 樂齡理財」。每個 Tab 都顯示該分類的課程數量。當課程數量增長時，使用者不需要滾動整頁就能找到感興趣的課程。

### 4. 資訊層級優化
卡片從「全部資訊一次攤開」改為「先吸引注意、再深入了解」的漏斗式設計。封面圖負責視覺吸引、標題和副標題負責傳達價值、2 條精選亮點負責強化購買動機、價格和 CTA 負責引導行動。完整資訊保留在課程詳情頁。

### 5. 無障礙性改善
篩選 Tab 加入了完整的 ARIA 屬性（tablist、tab、aria-selected、aria-label），讓螢幕閱讀器使用者也能正確理解和操作篩選功能。

## 三、Harness 工程系統開發流程的優點

本次開發使用了 Harness 虛擬團隊工作流，從需求到部署共經歷 6 個階段、5 個角色協作。以下是觀察到的優點：

### 1. 結構化需求避免了返工
PM 角色在第一階段就拆出 4 個 User Story 和 16 條驗收標準，並明確定義了「範圍外」的項目（例如不改詳情頁、不改資料結構）。這避免了開發過程中的 scope creep，也讓後續的 QA 測試有明確的對照標準。

### 2. 架構決策前置，降低實作風險
Tech Lead 在第二階段就做出了關鍵決策：Server/Client 組件拆分方式、圖片生成策略、不引入新依賴。這些決策在使用者確認後才進入實作，避免了「做完才發現方向不對」的浪費。

### 3. 角色分離帶來品質護欄
每個角色有明確的「可以做」和「不可以做」邊界：
- PM 不碰技術決策
- Frontend 不碰架構設計
- QA 不修改程式碼，只回報問題

這種分離確保了在同一個 AI 會話中，不同階段以不同的思維模式運作，而不是混在一起做。

### 4. Code Review 發現了 2 個潛在 Bug
Tech Lead 的 Code Review 階段發現了：
- FeaturedCard 沒處理 `isExternal` 的外部連結情況（潛在 bug）
- 未使用的 Badge import（程式碼品質）
- 缺少 ARIA 無障礙屬性（可及性問題）
- coverImages 硬編碼的維護性問題

這些問題在部署前就被修正了。如果沒有獨立的 Code Review 階段，這些問題很可能被忽略。

### 5. QA 驗收標準化測試
QA 角色不是隨意點點看看，而是逐一對照 PM 定義的 16 條驗收標準進行測試。每條標準都有明確的通過/不通過判定。這確保了交付品質的一致性。

### 6. Checkpoint 機制保護使用者決策權
流程中有 3 個 Checkpoint（需求確認、架構確認、部署確認），讓使用者在關鍵節點可以調整方向。本次開發中，使用者在 PM Checkpoint 要求加入圖片和篩選功能，這些需求被自然地納入後續流程。

### 7. 完整的可追溯性
每個階段都有結構化的輸出（需求文件、架構方案、實作摘要、Review 報告、測試報告），任務紀錄保存在 `docs/tasks/log.md`。未來回顧這次變更時，可以清楚知道為什麼做了這些決策。
